# Blue Nether Mod — Content Specification

## Overview

This document describes every content category needed to build an exact clone of the Nether recolored blue. "Blue" is the selected palette; all textures, particles, fog, and lighting should shift toward blue tones. Texture work is performed by the `fabric-writer` code generator at project scaffolding time (`tint_texture()` in `src/commands/test_project.rs:229`): each vanilla texture PNG is copied from the local Minecraft source, converted to grayscale via Rec. 601 luminance (`0.30*R + 0.59*G + 0.11*B`), and then tinted to the blue palette color `#5078FF` (the Blue Nether identity color used throughout the codegen). This keeps the blue tint swappable to another color later and minimizes manual texture work. RGBA transparency is preserved through the tint pipeline (e.g., `netherite_ingot` retains 121/256 transparent pixels matching vanilla). The tinted PNGs are committed directly to the mod's resource pack; no runtime tint provider is required for blocks, items, or mobs.

## Texture Asset Plan

All textures should be sourced (copied, not moved) from:

```
E:\Coding_Projects\MCSourceCode\vanilla-minecraft\26.2\assets\minecraft\textures
```

Available texture directories:

- `block/` — all block textures
- `item/` — all item textures
- `entity/` — all entity and mob textures (ghast, blaze, skeleton, enderman, etc.)
- `mob_effect/` — potion and effect icons
- `particle/` — particle textures (flame, soul fire, lava, drip)
- `painting/` — painting textures (if any Nether-themed paintings exist)

**Workflow for each texture:**

1. Copy the vanilla PNG to the mod's resource pack.
2. Desaturate the texture to neutral gray using Rec. 601 luminance (`0.30*R + 0.59*G + 0.11*B`).
3. Tint the desaturated texture to blue (`#5078FF`) during project scaffolding via the fabric-writer `tint_texture()` function in `src/commands/test_project.rs:229`. The tint formula is `result[i] = gray[i] * tint[i] / 255`, where `tint` is the RGBA pixel from the target blue palette. RGBA transparency is preserved (e.g., `netherite_ingot` retains 121/256 transparent pixels matching vanilla).
4. Keep the texture "recognizable" — it should be obvious what vanilla block it corresponds to, just blue-tinted.

## Future: Vanilla Asset Extraction

Current texture and sound copying assumes a local MCSourceCode checkout on the developer's machine. That is fine for prototyping, but not portable. A future CLI enhancement should support extracting assets directly from a vanilla Minecraft jar:

- **Asset source**: point the CLI at a vanilla `minecraft-<version>.jar`
- **Texture extraction**: extract `assets/minecraft/textures/{block,item,entity,mob_effect,particle}`
- **Sound extraction**: extract `assets/minecraft/sounds`
- **Workflow**: user supplies jar path → CLI extracts needed textures/sounds → preset copies them into the mod's resource pack with blue-tint metadata
- **Benefit**: removes the hardcoded MCSourceCode dependency and makes the preset usable by anyone with a vanilla Minecraft installation

This extraction feature is out of scope for the current implementation. For now, textures and sounds are copied from the local MCSourceCode paths documented above.
